## 3. 新增差距证据链（七问逐条，源自 A 发现、本轮回源复核）

### 差距 E：截图素材与展示尺寸脱节，图片体积与仓库膨胀无人设限

1. **原来怎么说**：B V1.0 全文未覆盖图片维度；上一轮 Lessons §4.3 把「截图规格调整」整体归为正常演化，未立任何规格约束。
2. **后来实际怎样**：README 三图显示宽 200 px（README.md:10-12，直接证据）；A 实测素材宽 2,174 px、最高 10,092 px，`6a3139e` 重截后单图 4,090,358 B、合计 +1.70 MB，`.git` 36 MB / 349 loose objects（A 实测，不可复核；三 PNG 存在为 Glob 直接证据）。
3. **差在哪里**：`30772d6` 改展示尺寸、`6a3139e` 重截素材，两次动作都没有「素材按显示宽度的倍率出、单张体积上限」的约束——改小展示反而喂给浏览器更大的原图。
4. **为何本应提前思考**：图片是纯派生物，规格是 Day 1 一句话（A 第八节⑤）；10-29 已重截过一次，第二次重截前正是立规时点。
5. **不提前造成何种返工**：每次重截 +1.7 MB 永久进 git 历史，仓库体积对所有 clone 永久收费；README 加载 4 MB 图只显示 200 px，访客流量浪费。
6. **下次普通人怎么说**：「图按显示大小的两倍出，一张不超过 300 KB；超了就截局部，别把整页长图塞进仓库。」
7. **提前明确的收益**：消除 MB 级历史膨胀；截图从「随手重截」变成「按规格出」的一次性动作。
